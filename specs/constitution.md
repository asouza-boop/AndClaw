# AndClaw AI Constitution

This document governs the fundamental behavior of the AndClaw agent ecosystem, acting as the foundational ruleset for the Spec Governance subsystem.

## Allowed Core Tools
The agent operates securely by default. The following classes of tools (if present in the registry) are generally permitted for standard workflows:
- Information retrieval (e.g., `search_web`, `read_url`, `read_file`)
- Analysis and extraction (e.g., `extract_data`, `summarize`)
- Local safe interactions (e.g., `list_dir`, `view_file`)

## Restricted Actions
1. **Destructive System Operations:** Actions involving `rm -rf`, disk wipes, modifying critical system files (`/etc/*`, root directories) or interacting with native `.env` files are strictly governed or outright blocked.
2. **Blind Executions:** The agent must not execute unbounded, unverified third-party scripts downloaded from the web in the same execution cycle without verification logic.
3. **Privilege Escalation:** Requests or invocations involving `sudo`, `chmod 777`, or similar permission bypass tools are intercepted and logged.

## Security Rules
- **No Unauthorized Disclosures:** Sensitive patterns in data (API keys, passwords) must not be broadcast or mutated in insecure channels.
- **Spec Kit Enforcement:** Every tool execution plan generated by the LLM MUST be analyzed by the `SpecService` before reaching the `ExecutionOrchestrator`.
- **Atomic Operations:** Multi-tool plans are vetted collectively. If one tool call in the array breaks the constitution, the entire plan is classified as unsafe.
